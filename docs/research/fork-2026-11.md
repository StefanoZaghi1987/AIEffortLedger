# Forked sessions in Claude Code — test of November 2026

Point-in-time test of 18 November 2026 with Claude Code 2.1.327, in an empty temporary folder: one headless prompt,
then the same prompt with `--continue --fork-session`. Only record types, key names, and identifiers were read; the
transcripts were deleted afterwards. This file is not updated.

## Result

- The fork is a new session with a new identifier and a file of its own.
- The fork file holds a copy of every record of the original that has a `uuid` (all 18). A copy keeps `uuid`,
  `parentUuid`, `timestamp`, and `message.id` of the original, but its `sessionId` is the identifier of the fork.
- Records without a `uuid` (queue operations, API request records, metadata records) are not copied: the fork writes
  its own, with timestamps after the fork.
- No field names the original session or the fork instant. The first record of the fork's own has a `parentUuid` that
  points to the last copied record.
- The original keeps, inside the time range of the copied records, records without a `uuid` of its own (queue
  operations and API requests); the fork holds none there.

## Limits

- `/branch` (formerly `/fork`) is interactive and was not tested; the changelog of 2.1.118 says that it "writes a
  pointer and hydrates on read", so its file can differ.
- The original did not continue after the fork; a fork whose original continues was not observed.
